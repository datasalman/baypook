## `src/server/checkout.ts`
`startCheckout(db, { holdId, customer, birthdayChild?, message?, accept, returnUrl?, payInStore?, origin? })`: validate the hold (`getActiveHold` → HOLD_EXPIRED), re-quote from the hold's lines, create the customer and pending booking, pick the return base (`returnUrl` if its origin is in `env.allowedOrigins()` or equals `env.baseUrl()`; else `WEBSITE_URL ?? BAYPOOK_URL` + `/book/thanks`), build `successUrl = base?paid=1&venue=<slug>&booking=<token>` and `cancelUrl = base?cancelled=1&venue=<slug>`, then `getPaymentProvider(venue.slug)` (null → UNAVAILABLE, and cancel the pending booking) and `createCheckout` with line items from the quote, `expiresAt = hold.expiresAt`; insert a `payments` row status pending with the checkout id; store `checkoutId` on the hold. Return `{ bookingId, reference, checkoutUrl }`. Pay-in-store path when `service.payInStoreEnabled && payInStore`: booking confirmed with paymentStatus owed, send confirmation email, calendar create, return `{ bookingId, reference, token, confirmed: true, thanksUrl }`.

## `src/server/webhooks.ts`
`handleStripeEvent(db, { venue, event })`: idempotency via `processed_webhook_events` (insert first; on conflict return `{ duplicate: true }`). ## Deviations (Agent D1, as built)

- **Pending vs pay-in-store holds.** `createPendingBookingFromHold` finds or creates the customer itself (from `organisation.id` + the customer fields). Online: booking `pending`/`unpaid`, hold attached with `attachHoldToBooking` (stays active as the expiry timer). Pay in store: booking `confirmed`/`owed`, hold `converted`.
- **Reference collisions** are retried inside a savepoint (`tx.transaction`) so a unique violation does not abort the outer transaction.
- **`confirmBookingPaid`** locks the booking row, then checks idempotency (succeeded payment with the same checkout id or payment intent; a payment-intent-only event also matches a succeeded payment that has no intent id yet, and fills it in). It updates the pending payment row to succeeded rather than inserting a second row. A payment for a booking that was already **cancelled** (hold lapsed) reinstates it if `assertBookable` (ignoreTiming) still passes; otherwise the payment is recorded, the booking stays cancelled and the owner gets an alert e-mail (`owner_alert`) to refund it. Emails use `dedupe: true`.
- **`paymentStatus`** is derived by an exported `derivePaymentStatus(booking)` (refunded/partially_refunded when anything is refunded; unpaid for online with nothing paid; owed when paid < total; else paid).
- **`cancelBooking`** checks the transition and refund permission before anything changes, refunds first (so a failed card refund leaves the booking untouched), then cancels. A pending booking cancelled by an admin gets no cancellation e-mail.
- **`refundBooking`**: amount above `paid − refunded` → `LIMIT` with `limit`; it refunds one payment per call (online first, then the largest); if no single payment covers the amount → `LIMIT` with that payment's remainder. Provider failures → `UNAVAILABLE`. Pending provider refunds count towards `refundedPence` (the `charge.refunded` webhook settles them).
- **Extra exports** in `bookings.ts`: `toBookingError`, `derivePaymentStatus`, `recordProviderRefund` (used by the webhook for refunds made in the Stripe dashboard, which also e-mails the customer), `findBookingIdByCheckout`, `describeBooking`, types `BookingDetail`, `BookingListItem`, `BookingSummary`. `BookingError` also carries `reason`.
- **`listBookings`** returns `BookingListItem[]` (`{ booking, customer, service, venue }`), `venueIds: string[] | null` (null = all), `status` may be an array, extra `order: "asc" | "desc"` (default asc).
- **`createManualBooking`**: customer e-mail is optional (walk-ins); a blank e-mail always creates a new customer and no e-mail is sent. No owner party alert for staff-made bookings.
- **`moveBooking`** keeps the booking's current length for slots (includes Food time) and clears `reminderSentAt`. `changeBookingCounts` recomputes a slot's end from the new add-ons.
- **`getCustomerWithBookings(db, id, { venueIds })`** takes an optional venue scope for staff/managers. `searchCustomers` also matches phone numbers ignoring spaces.
- **`startCheckout`**: the payment provider is checked *before* the booking is created (no provider → hold released, `UNAVAILABLE`), so nothing has to be cancelled. Pressing Pay twice with the same hold supersedes the earlier pending booking (cancelled as `abandoned`, its checkout expired). `origin` is accepted but unused. Return-URL helpers exported: `chooseReturnBase`, `buildReturnUrls`, `saveDemoReturnUrls`, `getDemoReturnUrls`.
- **Demo checkout return URLs** are stored in `settings` under `demo.checkout.<bookingId>` (demo mode only); the demo page's Pay/Decline actions read and delete them (falling back to the default `/book/thanks` base when missing).
- **Webhooks**: `handleStripeEvent` reads event objects structurally (`WebhookEvent = { id, type, data: { object: unknown } }`; `Stripe.Event` is assignable), so it does not depend on the Stripe SDK's type layout. If handling throws, the `processed_webhook_events` row is deleted so Stripe's retry is processed (the route then returns 500). Also handles `checkout.session.async_payment_succeeded`. `charge.refunded` works with or without the expanded `refunds` list (falls back to reconciling `amount_refunded`). Dispute alert template name `owner_dispute`. Extra export `listDisputedPayments`.
- **API**: `remaining` in session availability is 0 whenever the session is not bookable (so a room-busy session shows 0); past sessions are omitted; cancelled ones are listed with reason `cancelled`; the core reason `closed` is reported as `blocked`. Every day in the window is returned (possibly with no sessions). Services include `slotIntervalMinutes: null` for sessions. Venue `postcode` is `""` when unset. Summary includes `timezone`. Added `DELETE /api/v1/holds/:id` (also cancels a pending booking already made from that hold). Error codes `FORBIDDEN` (403) and `STATE` (409) exist in `lib/api.ts` for completeness. `withApi` also catches `ApiError` (thrown by routes). `resetRateLimits()` exported for tests.
- **Jobs**: `runJob` never throws (returns the failed `job_runs` row). Extra `runExpireHoldsJob(db, triggeredBy, now?)` and `listJobRuns(db, { limit, job? })`. Cron route returns 500 when the job failed.
- **Cron auth** `authoriseCron(req)` returns `null` when allowed, else the 401 `Response`.
- **Tests** use `vi.mock("@/db")` for `getDb` and fake `Date` (`vi.useFakeTimers({ toFake: ["Date"] })`) so the fixed October 2026 dates stay in the future.
